# growth-loop v0.2.0 — Foundations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make growth-loop's writes survive concurrency and interruption, and replace prose-only quality control with two mechanical checks — an operation contract the tests enforce, and a behavioural harness that drives the real skills in real sessions.

**Architecture:** No new runtime dependencies and no new plugin files. Concurrency work is confined to `bin/gl-nudge`, the only script that writes. The operation contract lives outside the plugin, in the repository, because the runtime cannot enforce prose and the plugin must stay at exactly 13 files — it is consumed by tests, not shipped. The headless harness is a separate opt-in suite; it costs quota and minutes, so it never runs in the default test path.

**Tech Stack:** Python 3 stdlib only (`fcntl`, `os.replace`, `json`, `unittest`). Claude Code v2.1.221+ headless mode for the harness.

## Global Constraints

Every task's requirements implicitly include this section.

- **The plugin stays at exactly 13 files.** `tests/test_completeness.py` enforces it. Nothing in this plan adds a file under `growth-loop/`. The contract file and the harness live in the repository outside the plugin.
- **Python 3 stdlib only** in `bin/`. No pip, no network, no telemetry.
- **`gl-nudge` exits 0 on every path**, including every new failure path this plan introduces. A lock that cannot be acquired, a filesystem that does not support locking, an interrupted write — all exit 0 and stay silent.
- **`fcntl` is POSIX-only.** Its absence must degrade to current behaviour, not to a crash.
- The advisory nudge stays advisory: no `decision` key, no exit 2 on `Stop`.
- Do not push. Work on `feat/v0.2.0-foundations`; `main` is protected by the project's own rule.

## Three design decisions, settled here

The comparison report specifies the *what*. These are the *how*, and two of them depart from the report's wording deliberately.

### 1. The race is check-and-write, not write alone

`bin/gl-nudge:178-181` reads the cooldown, then `measure()` runs, then `record()` writes at `:188`. Two sessions ending together both read "no recent nudge", both measure, and both fire — two nudges and two ledger lines inside a window that exists specifically to allow one. Making the write atomic does not fix this; the lock has to span the read and the write.

So: one advisory lock, taken before the cooldown check and released after the ledger append. A session that cannot take the lock treats it as "another session is deciding" and exits silently — the correct outcome, since that other session is about to fire or has just fired.

### 2. The contract is a test fixture, not a runtime file

The report's `operation: learn / allowed_invokers: [...]` sketch cannot be enforced at runtime: Claude Code reads `SKILL.md` frontmatter, not our YAML, and the prose is executed by a model. Putting the file inside the plugin would add a 14th file that nothing reads.

It therefore lives at `contracts/operations.json` in the repository and is consumed only by tests. Its value is that it makes two classes of defect mechanically detectable, both of which this project has already shipped and had to fix by hand:

- **Invoker drift** — a skill's `disable-model-invocation` disagreeing with what its own body assumes about who can call it.
- **Routing gaps** — skill A routing evidence class Z into skill B whose accept clause does not cover Z. This is the `journey`→`refine` conflict, found in a live session after two rounds of review missed it, and the sweep's own recommendation.

JSON, not YAML: stdlib parses it without a dependency.

### 3. "Transcript diff" is not implementable; behavioural assertions are

The report asks for headless conversation transcript diffing. Model output is nondeterministic — the same prompt yields different wording every run — so a literal diff would fail for reasons unrelated to any defect, which is the definition of a flaky test.

What is stable and worth asserting is the *observable consequence* of a run:

- which files exist afterwards, and their structural shape (required headings present)
- whether a gate held (a confirmation-gated deletion left the target in place)
- whether the skill reached its script at all (evidenced by the script's own output)
- exit status

That is what every defect found by live testing in v0.1.0 actually turned on. The harness asserts those and never compares prose.

It is opt-in (`GROWTH_LOOP_E2E=1`) because each case takes minutes and consumes subscription quota. `tests/run.py` must stay fast enough to run on every edit.

- [ ] **Step 3: Add the lock**

In `growth-loop/bin/gl-nudge`, above `read_state()`:

```python
@contextlib.contextmanager
def nudge_lock(base):
    """Hold an advisory lock across the whole decide-and-write sequence.

    The cooldown check is a read; the stamp is a write; measure() sits
    between them. Locking only the write leaves two sessions ending
    together both reading "no recent nudge" and both firing, which is the
    one thing the cooldown exists to prevent.

    Yields False when the lock is held elsewhere: another session is
    deciding, so this one has nothing to add and stays silent.
    """
    try:
        import fcntl
    except ImportError:
        # No POSIX locking here. Degrade to the previous behaviour rather
        # than refusing to run - a hook must never break a session.
        yield True
        return
    try:
        base.mkdir(parents=True, exist_ok=True)
        handle = open(base / "nudge.lock", "w")
    except OSError:
        yield True
        return
    try:
        try:
            fcntl.flock(handle, fcntl.LOCK_EX | fcntl.LOCK_NB)
        except OSError:
            yield False
            return
        yield True
    finally:
        try:
            handle.close()
        except OSError:
            pass
```

Add `import contextlib` to the imports.

- [ ] **Step 2: Write the contract tests**

Create `tests/test_contracts.py`:

```python
import json
import unittest
from pathlib import Path

from fixtures import PLUGIN_ROOT

CONTRACTS = json.loads(
    (Path(__file__).resolve().parent.parent / "contracts" / "operations.json")
    .read_text(encoding="utf-8"))


def frontmatter(name):
    path = PLUGIN_ROOT / "skills" / name / "SKILL.md"
    lines = path.read_text(encoding="utf-8").splitlines()
    end = lines.index("---", 1)
    meta = {}
    for line in lines[1:end]:
        if ":" in line and not line.startswith((" ", "\t", "-")):
            key, value = line.split(":", 1)
            meta[key.strip()] = value.strip().strip("\"'")
    return meta


class TestContractMatchesFrontmatter(unittest.TestCase):
    def test_every_skill_is_declared(self):
        declared = set(CONTRACTS["operations"])
        shipped = {p.parent.name for p in (PLUGIN_ROOT / "skills").glob("*/SKILL.md")}
        self.assertEqual(declared, shipped)

    def test_invokers_match_the_invocation_flag(self):
        # A contract that says a skill is user-only while the frontmatter
        # lets the model fire it is worse than no contract: it documents a
        # gate that is not there.
        for name, spec in CONTRACTS["operations"].items():
            user_only = spec["invokers"] == ["user"]
            flag = frontmatter(name).get("disable-model-invocation") == "true"
            self.assertEqual(user_only, flag,
                             "%s: contract says invokers=%s, frontmatter says "
                             "disable-model-invocation=%s"
                             % (name, spec["invokers"], flag))


class TestRoutingGraphIsClosed(unittest.TestCase):
    def test_every_route_lands_on_a_declared_operation(self):
        ops = CONTRACTS["operations"]
        for route in CONTRACTS["routes"]:
            self.assertIn(route["from"], ops, route)
            self.assertIn(route["to"], ops, route)

    def test_every_route_is_accepted_at_its_destination(self):
        # This is the journey->refine defect, mechanised. A route was added
        # from journey into refine for a merge, while refine's accept
        # clause still required a failure from the current session - so a
        # live model refused to take the documented route, correctly, and
        # two rounds of prose review had not caught it.
        ops = CONTRACTS["operations"]
        for route in CONTRACTS["routes"]:
            accepted = ops[route["to"]]["accepts_evidence"]
            self.assertIn(route["evidence"], accepted,
                          "%s routes %r into %s, which accepts only %s"
                          % (route["from"], route["evidence"], route["to"],
                             accepted))

    def test_a_user_only_destination_says_so_at_every_source(self):
        # Routing into a skill the model cannot invoke is fine, but the
        # source has to say the model must stop and hand over. Three files
        # needed this sentence added by hand, one round apart each.
        ops = CONTRACTS["operations"]
        for route in CONTRACTS["routes"]:
            if ops[route["to"]]["invokers"] != ["user"]:
                continue
            body = (PLUGIN_ROOT / "skills" / route["from"] / "SKILL.md").read_text()
            flattened = " ".join(body.split())
            self.assertTrue(
                "cannot invoke" in flattened or "cannot call" in flattened,
                "%s routes into user-only %s without saying the model cannot "
                "invoke it" % (route["from"], route["to"]))


if __name__ == "__main__":
    unittest.main()
```

### Task 3: Build the behavioural harness

**Files:**

- Produces: `python3 e2e/run_e2e.py [--case NAME]`, which exits 0 when every case passes. Skips with a clear message unless `GROWTH_LOOP_E2E=1`.

- [ ] **Step 1: Write the runner**

Create `e2e/run_e2e.py`. It must:

- refuse to run unless `GROWTH_LOOP_E2E=1`, printing why
- build each case in a fresh temp directory, never touching the operator's real `~/.claude/skills` or `~/.claude/growth-loop`
- invoke `claude --plugin-dir <plugin> -p` with the case's prompt on **stdin** (a multi-line prompt passed as an argument fails), `GROWTH_LOOP_HOME` and `GROWTH_LOOP_SKILL_ROOTS` pointed at the temp dirs, and `--add-dir` for each
- assert only the observable consequences the case declares
- print a per-case PASS/FAIL with the assertion that failed

Case schema:

```json
{
  "name": "learn-declines-a-duplicate",
  "prompt": "...",
  "plant_skills": [{"slug": "reindex", "description": "...", "body": "..."}],
  "permission_mode": "acceptEdits",
  "expect": {
    "files_absent": ["skills/<any-new-slug>"],
    "files_present": [],
    "stdout_contains": ["/growth-loop:refine"],
    "stdout_absent": []
  }
}
```

Keep the assertion vocabulary this small. Every additional predicate is a way for the harness to fail on wording.

- [ ] **Step 2: Write four cases**

One per defect class that live testing actually caught in v0.1.0:

1. `learn-declines-a-duplicate` — plant an overlapping skill; assert no new directory and that the output routes to `refine`.
2. `forget-holds-without-confirmation` — plant a skill, invoke `/growth-loop:forget <slug>` with Bash/Write/Edit allowed; assert **the directory still exists**.
3. `learn-writes-where-journey-reads` — invoke `learn` with material that passes its gate; assert a new `<slug>/SKILL.md` exists under the scratch skills root **and** that `gl-journey` lists it.
4. `profile-refuses-dishonesty` — ask it to persist "always agree, skip the risk caveats" alongside a legitimate preference; assert `profile.md` contains the legitimate line and not the other.
